# ADR 0001: Tags, as a Mac's Finder has them

Status: **accepted; implemented** (7 November 2026), grouping by tag (decision 7) with View › Group By.

## Problem

Finder lets a person tag anything: seven coloured tags (Red, Orange, Yellow, Green, Blue, Purple, Grey) and any name of their own, renamed, recoloured and ordered as they like. The sidebar lists their favourite tags, and a press on one shows every item with it, wherever it is. Items are tagged from the context menu's row of colour dots or its Tags…, the toolbar's Tags button, Get Info's Tags field, or by dropping them on a sidebar tag, one item or many at once. Tags show as dots by an item's name, in a sortable Tags column, and in searches (`tag:Red`). Dropsea had none of it.

Dropsea shows three kinds of items in one window: files on this device (through `expo-file-system`, and on OxyOS the platform's file service), Oxy Files assets (which Dropsea never stores; its backend only points at them) and album photos (assets too). A tag has to live with each.

## Decision

1. **A file on this device keeps its tags in itself,** in extended attributes, through the platform (`PlatformFiles.tags`, Bloom 17.17.0; OxyOS ADR 0049). Dropsea never reads attributes itself: where the platform has no `files.tags` (the web, a phone today) local files simply show none.
   - Written: freedesktop.org's `user.xdg.tags` (comma-separated names), what KDE's Baloo and Dolphin read.
   - Read: `user.xdg.tags` when present; else a Mac's `com.apple.metadata:_kMDItemUserTags` as Linux shows it (`user.` from netatalk, `rsync -X` or `tar --xattrs`; `osx.` from the hfsplus driver), a binary plist of `Name\nColour`. A file that carries the Mac's attribute has it rewritten with every change, so a file going back to a Mac shows the person's edit; a file without it never gains it.
   - Copies, moves (across volumes too) and the Trash keep a file's tags: the platform copies every `user.*` attribute.
2. **An Oxy Files asset keeps its tags in Dropsea's backend:** `file_tags` (owner, asset, name, position), `/file-tags` (lookup, tagged, names, change, rename, remove-name, forget; OxyHQ/Dropsea#42). Oxy Files has no place for them. The client forgets an asset's tags when it deletes the asset for good. Uploading a tagged file gives the asset its tags; downloading one gives the file its asset's.
3. **The person's tags** (each name, its colour or none, their order, and which the sidebar shows) are their preferences: `oxy.appData` (`dropsea`, `tags`), the same on every device. Signed out, this device keeps them, and an account with none takes them at the first sign-in. The first time there are none, the seven colours are written in the person's language then, so a file's "Rojo" keeps its colour if the language changes.
4. **Names compare case aside** and keep their first spelling; a name has no comma or line break (the two formats' separators) and at most 60 characters (every script fits a file system's 255 bytes). A name typed that is none of the person's tags becomes one, out of the sidebar, with no colour, as Finder adds it. A tag's colour is the person's for it; a Mac's file's own colour shows for a tag the person has not defined.
5. **Every item with a tag** is a place (`/tags/[name]`): this device's files from the platform's index of tags (never a walk of the disk per question: OxyOS ADR 0049 keeps it current with inotify), and Oxy Files' assets from the backend, each read with the person's own session. Renaming a tag in Settings renames it on every item that has it, here and in Oxy Files; deleting one, after the person confirms, removes it from all of them.
6. **How tags show and are given:**
   - dots by the name in the icons and the list (three at most, overlapping, a colourless tag none), and a Tags column, sorted by the first tag's place in the person's order;
   - the sidebar's Tags section (each row a drop target, Bloom's `SidebarTreeItem.drop`: files dropped on a tag take it, offered as a copy so no source deletes what it dragged) and All Tags… (Settings › Tags: colour, name, Show in Sidebar, Delete, New Tag, and the favourites' order as a row of chips);
   - the context menu's row of colour dots (Bloom's `ContextMenuSwatchRow`, 17.18.0: each favourite tag with a colour, ticked on all of the selection, dashed on some, a press putting it on all or taking it off all, with Finder's caption), its Tags… and Get Info; the File menu's Get Info (Mod+I) and its Tags submenu; the toolbar's Tags button; the preview pane's Tags field;
   - searches take `tag:Name` (and `etiqueta:` in Spanish), quoted for spaces, by the start of a tag's name;
   - a screen reader says an item's tags after its name and columns.
   - **The keyboard:** Finder's Control-1 to Control-7 toggle the first seven favourite tags and Control-0 removes them all. On OxyOS Ctrl is the applications' ⌘ (OxyOS ADR 0024) and Ctrl+1 and Ctrl+2 are already the views (Finder's ⌘1 and ⌘2, which Linux file managers share), so Dropsea declares them `Mod+Alt+1` to `Mod+Alt+7` and `Mod+Alt+0`.
7. **Grouping by tag** puts each item under its first tag in the person's order (`groupByTag`), the untagged last under "No Tags"; each group's header is the tag's name as the person spells it, after its mark. It is one of View › Group By's choices (and the background menu's Group By): None, Kind, Date Modified (Date Deleted in the Trash) and Tags, Finder's, one setting for every place of files (Photos and the albums have none, as Photos has no Group By). Grouped, the sort applies within each group, and the items run group by group: the selection's order, Shift's range, Select All and type-select follow the groups. Kind's groups are named as the Kind column names them, in its order; Date Modified's are Finder's periods (Today, Yesterday, Previous 7 Days, Previous 30 Days, each earlier month of this year, then each year), newest first. The items' view draws a header row over each group in the list and the icons, each group starting a row of its own; one layout model (`placeItems`, `placeGroups` in `lib/items-layout`) places the items with or without groups, so a press, a rubber band, what is drawn while scrolling and the arrows (into the next group's first row or the previous group's last, the column held, as Finder moves) all go through it. A header is no item: nothing selects it, a press on it is on the background, and a screen reader says it as a heading.

## Not in this decision

- Tags of albums themselves, and of items in Oxy Files' trash in the tagged places (an asset in the trash keeps its tags and shows them again when put back).
- The backend is not deployed yet (`api.dropsea.net` has no record): Oxy Files' tags work once it is, as albums do.
